# Cortech Consulting Group — Proposal Structure & Style Guide

*Synthesized from 104 submitted proposals (81 .docx with reliable Heading styles; 23 .pdf with heuristically-detected headings — treat PDF-derived patterns as directional, not exact, since they sometimes capture running headers, table cells, and cover-page fragments repeated on every page).*

---

## 1. The Core Section Skeleton (What Cortech Actually Does)

Across the docx corpus — the most trustworthy signal — a consistent backbone recurs even though section numbering and exact labels vary considerably. The typical full technical proposal moves through:

1. **Cover Letter / Submission Letter** — almost always the first Heading 1 (e.g., *Technical Proposal 5*, *Technical Proposal IGAD*, *Technical Proposal CARE*, *RfP_UNICEF.docx* uses "Submission Letter")
2. **Organisational Profile / Consultant's Organisation** — "About Cortech Consulting Group," "Our Expertise/Our Experience," sometimes "Our Services," "Certificates" (seen in *RfP_UNICEF.docx*, *DRC TECHNICAL PROPOSAL.docx*, *RACIDA TECHNICAL PROPOSAL.docx*)
3. **Related Previous Assignments / List of References** — a track-record section, often just before or after the ToR section (*Technical Proposal IGAD*, *Technical Proposal 3*, *Technical Proposal SCI*)
4. **Understanding/Introduction & Background** — covers rationale, purpose, objectives, scope, deliverables, "our interpretation of the assignment" (nearly universal, appears in almost every docx)
5. **Proposed Approach and Methodology** — the largest section, broken into phases (Inception → Data Collection → Analysis → Reporting), frequently using numbered sub-headings
6. **Quality Assurance / Ethical Considerations / Safeguarding** — often a standalone Heading 1
7. **Risk Analysis and Mitigation** — standalone, almost always present
8. **Workplan / Timelines / Gantt Chart** — standalone
9. **Proposed Personnel / Team Composition** — standalone, sometimes with a qualifications matrix
10. **Annexes** — CVs, Registration Information, Financial Proposal, Work Schedule

This order is stable enough to use as a default skeleton, but **do not treat it as rigid** — see variation notes below.

## 2. Documented Variation (Be Honest About It)

**A. Two distinct "template families" exist:**

- **The "Numbered ToR-response" family** (e.g., *Technical Proposal IOM.docx*, *Technical Proposal ACEF.docx*, *Technical Proposal ZIZI Afrique.docx*, *Technicap Proposal Concern WorldWide*): uses lettered/numbered macro-sections like "A. UNDERSTANDING THE TERMS OF REFERENCE," "B. PROPOSED APPROACH AND METHODOLOGY," "C. RISK MANAGEMENT & MITIGATION PLAN," "D. WORKPLAN AND TIMELINES," "E. PROPOSED CORE PERSONNEL," "F. ANNEXES." This is common for IOM/GIZ-style donor formats.

- **The "GIZ/technical-cooperation" family** (e.g., *DRC TECHNICAL PROPOSAL.docx*, *Part II_Technical_Proposal_SRI.docx*, *Technical_Proposal_Agricultural_Processing...docx*, *Technical proposal _Cortech_GIZ.pdf*): follows a distinct GIZ-specific rubric — **STRATEGY → COOPERATION → STEERING STRUCTURE → PROCESSES → LEARNING AND INNOVATION → PROJECT MANAGEMENT → ORGANIZATION AND STAFFING**. This is a fixed donor-mandated structure, not Cortech's free choice — use it only when responding to GIZ ToRs.

**B. Some proposals skip the profile/experience sections entirely** and start directly with technical content (*Technical Proposal 9.docx* has only "Team Composition"; *Technical Proposal PGI (1).docx* has no headings at all; several docx files show **empty heading arrays** — meaning body text was likely used without styled headings, e.g., *SRDI PROPOSAL UN WOMEN.docx*, *Technical Approach and Methodology.docx*, *Technical Proposal Cortech to SOS CV Somalia.docx*). This suggests inconsistent internal QA on heading styling — worth flagging to whoever finalizes documents.

**C. Numbering conventions are inconsistent between proposals:**
- Some use decimal numbering (1.1, 1.2, 2.1...) — *TECHNICAL PROPOSAL 1.docx*, *WHH TECHNICAL PROPOSAL.docx*, *RACIDA TECHNICAL PROPOSAL.docx*
- Some use bare Arabic numerals per section (1., 2., 3.) — *Technical Proposal 3.docx*, *Technical Proposal IOM.docx*
- Some use Section-prefixed headings ("SECTION 2: PROPOSED APPROACH...") — *Technical Proposal 31 Jan 2026.docx*, *Technical Proposal 7.docx*
- Some use lettered top-level with numbered sub-levels ("A. Consultant's Organisation" / "A.1", "A.2") — *DRC TECHNICAL PROPOSAL.docx*, *RACIDA TECHNICAL PROPOSAL.docx*, *WHH TECHNICAL PROPOSAL.docx*
- Some use Form-style labels ("Form TECH-1," "Form TECH-2"...) — *TECHNICAL_PROPOSAL_CEF-RFP-01...docx*, *Technical Proposal ICPAC Final.docx* — this only appears when the donor's RFP explicitly mandates a forms-based submission structure.

**Guidance:** Match numbering style to what the specific ToR/RFP asks for. Don't invent numbering conventions — mirror whichever family matches the closest prior submission to the same donor if one exists (e.g., GIZ jobs → STRATEGY/COOPERATION style; IOM/UN jobs → lettered A/B/C style).

**D. Capitalization is inconsistent even within the same family:**
- ALL CAPS Heading 1s are common in the "numbered ToR-response" family: "COVER LETTER," "ORGANISATIONAL PROFILE," "UNDERSTANDING THE TERMS OF REFERENCE" (*Technical Proposal 11, 13, 14, 15, ACEF, CARE, IGAD, SCI, ZIZI Afrique*)
- Title Case is used in the GIZ family and older/simpler proposals: "Submission Letter," "Introduction and Background," "Description of Approach, Methodology and Work Plan" (*20240729...Plan International Mapping.docx*, *DRC TECHNICAL PROPOSAL.docx*)
- **Recommendation:** Pick ALL CAPS for donor-facing formal RFP responses (matches the majority of recent, larger proposals) and Title Case for narrative-style technical write-ups. Do not mix within one document.

## 3. CV/Annex Sub-Structure (Highly Consistent)

Personnel CVs follow a near-identical template across nearly all proposals, docx and pdf alike — this is Cortech's most standardized content block:

- Numbered biodata fields: "1. Family name," "2. First names," "3. Date of birth," "4. Nationality," "5. Civil Status," "6. Based in/Residence"
- "8. Language skills" table (Reading/Speaking/Writing columns, rated 1–5 or Excellent/Good/Basic)
- "9. Membership of professional bodies"
- "11. Present position," "12. Years of Experience"
- "15. Professional Experience" — table with **Date | Location | Company | Position | Description** columns (very consistent, appears in *Cortech-Technical Proposal.pdf*, *Technical Proposal_Somalia Nutrition Cluster...*, *Technical Proposal_World Vision Endline Evaluation Somalia.pdf*, and others)

Use this exact numbered CV format for new proposals — it is the single most standardized artifact in the corpus.

## 4. Table Usage (Inferred from Heading Text)

Even though headings themselves aren't tables, several recurring heading fragments are clearly table headers/rows captured by the PDF heuristic parser — meaning these sections **should be built as actual tables** in the docx, not narrative headings:

- Financial Proposal sections: "Activity Description Unit Days Unit Cost Cost (USD)," "Personnel Costs," "GRAND TOTAL" (*20240409...NRC Market Survey.pdf*, *Technical Proposal_GIZ Remuneration Survey...pdf*)
- Team/staffing schedules: "Task Start Date End Date Duration Personnel Role/Responsibility" (*20241009...IoM_Monitoring Framework...pdf*)
- Sampling/methodology matrices: "Tool/Method Target," "Respondent Group Sampling Approach Sample Size" (*Cortech-Technical Proposal.pdf*, *Technical Proposal_ DRC BORESHA NABAD Project.pdf*)
- Risk matrices: "Risk Category Description of Risk Mitigation Strategy" (recurs in nearly every proposal with a Risk section)
- Work plans / Gantt charts: MS Project export artifacts like "Task Project Summary Inactive Summary Manual Summary External Milestone" appear repeatedly (*Operation Model of JUWA*, *Technical Proposal_Somalia EIE Consultancy.pdf*, *Technical proposal _Cortech_GIZ.pdf*) — confirms Cortech routinely embeds actual MS Project Gantt charts as images/objects in proposals, not just prose timelines.

**Guidance:** Always build Financial Proposal, Team Composition, Sampling Strategy, and Risk Mitigation sections as formatted tables, not paragraph text — this is consistently how Cortech presents this content, and PDF extraction confirms tabular origin even where the docx source isn't available for direct inspection.

## 5. Annex Naming Conventions

Highly consistent: **"Annex 1," "Annex 2," "Annex 3"** (numeric, not lettered) is the dominant style (*Technical Proposal_ DRC Mapping Formal Financial Service Providers*, *Technical Proposal to WHH 2.docx*, *20240729...Plan International Mapping.docx*). A minority use "ANNEX I," "ANNEX II" (Roman numerals) — this appears specifically in the "numbered ToR-response" family (*Technical Proposal 13, 14, 15, ACEF, CARE, IOM 18 Nov 2025*). Standard annex contents, in order of frequency:
1. Work Plan / Work Schedule
2. Risk/Mitigation Plan (sometimes folded into body instead)
3. Financial Proposal
4. Consultants' CVs
5. Registration/Incorporation Documents

Match Arabic vs. Roman numeral annex labels to whichever numbering family (Section A/B/C vs. plain numbered) you're using in the body — don't mix conventions.

## 6. Recommendations for New Drafts

1. **Default skeleton** (safe for most RFPs without a mandated format): Cover Letter → Organisational Profile → Related Experience → Understanding of Assignment/ToR → Proposed Methodology (phased) → Risk Management → Workplan/Timeline → Team Composition → Annexes (Work Plan, Financial Proposal, CVs, Registration Docs).
2. **Check the donor first**: If it's GIZ, use the STRATEGY/COOPERATION/STEERING STRUCTURE/PROCESSES format. If it's a UN agency with a forms-based RFP, use "Form TECH-1/2/3..." labels as directed.
3. **Be consistent in capitalization and numbering within one document** — pick ALL CAPS + numbered sections (A/B/C or 1/2/3) for formal RFP responses; Title Case for lighter/internal-style proposals.
4. **Always table-ize**: financial breakdowns, staffing schedules, sampling plans, and risk matrices.
5. **Use the standardized numbered CV format** (Family name, First names, Date of birth... through Professional Experience table) for every personnel annex.
6. Note: a non-trivial share of the docx source files show **no heading styles applied at all** — a quality-control reminder that headings should be tagged with Word Heading styles (not just bold text) for consistency and easier reuse/searchability going forward.
